verifynNGDesign systemv0.1 · foundations

One token set, three surfaces, one meaning of “genuine”.

verifynNG is a multi-tenant product-authenticity platform. Tenants may repaint the chrome. They may never repaint a verdict. This document sets the primitives, the semantic aliases, the verdict family and the rules that hold that promise across the consumer web, the tenant console, and print.

01 — Platform identity

Quietly confident. It recedes so the tenant can speak.

No shields, no padlocks, no green ticks borrowed from antivirus software. The platform mark is a graphite-blue and bone system that sits underneath tenant colour without competing with it — and, critically, occupies none of the hues the verdict family needs.

verifynng
The notch bar. Four cells, read left to right. It is the wordmark's underline, the scanner's progress track, and the shape signature that lets every verdict be told apart without colour.
Wordmark: Space Grotesk Medium, −3.5% tracking, lowercase throughout. The ng takes the platform accent; on a tenant surface it takes brand.primary.

Voice
Say“Authentic. First time this code has been checked.”
Not“✅ 100% GENUINE PRODUCT — VERIFIED!”
Say“This code has been checked 14 times before. That is unusual for a single unit.”
Not“⚠️ WARNING: POSSIBLE FAKE DETECTED”
Second person, present tense, no exclamation marks, no emoji. State what is known, then what is not. A verdict never accuses the person holding the phone.

03 — The verdict family

Four channels carry every verdict. Colour is only one of them.

Each state is identified by a shape signature in the notch bar, a glyph, a band texture, and a plain-language label — before colour is considered. Remove all colour and every state remains distinguishable, which is what makes the set safe under deuteranopia, protanopia and direct sunlight alike.

06 — Theming

IVORY GLOW, as the tenant would actually submit it.

Six keys in, validated, contrast-guarded, and resolved into the semantic layer. Anything outside the whitelist is rejected at save time with a named error — silently dropping it would let a tenant believe they had changed something they had not.

tenants/ivory-glow/theme.tokens.json
{
  "$schema": "w3c-design-tokens/1.0",
  "tenant": { "$value": "ivory-glow" },
  "brand": {
    "primary":   { "$type":"color", "$value":"#E3A93C" },
    "secondary": { "$type":"color", "$value":"#5C5140" },
    "surface":   { "$type":"color", "$value":"#F5F1E8" },
    "fg":        { "$type":"color", "$value":"#231C10" }
  },
  "font": {
    "display": { "$type":"fontFamily",
                 "$value":["Playfair Display","Georgia","serif"] },
    "body":    { "$type":"fontFamily",
                 "$value":["Inter","system-ui","sans-serif"] }
  },
  "radius": { "scale": { "$type":"number", "$value":1.5 } },
  "logo": {
    "light": { "$type":"asset", "$value":"ivory-glow/mark.svg" },
    "mono":  { "$type":"asset", "$value":"ivory-glow/mark-mono.svg" }
  }
}
Radius scale is a multiplier on the platform ramp, clamped to 0–2. IVORY GLOW's 1.5 turns 4/8/14 into 6/12/21.
Contrast guard — resolution order
1Measure brand.primary against brand.surface. If ≥ 4.5:1, use it for text and fills. Done.
2If not, darken in OKLCH by reducing L in 0.02 steps until 4.5:1 is met, holding chroma and hue. That result becomes brand.primary.readable.
3If L reaches 0.25 without meeting it, fall back to brand.fg and surface a warning in the branding editor.
4The declared value is retained as brand.primary.decorative for rules, fills behind large type, and the logo field — never for body text or a control label.

07 — Principles

Verdict first

The answer is the first thing painted and the first thing read aloud. Brand, product imagery and marketing come after it, or not at all.

Honest, not binary

Ten states, because reality has ten. “Already verified” is history, not a warning. “Unknown” is an absence of record, not an accusation.

Never show a full code

Every rendering is truncated — ivoryglow.2.k1.ABCD… — in the app, the console, the audit log, support tooling and email alike.

Constant trust semantics

A consumer who learns what amber means on one tenant knows what it means on all of them. This is why the verdict family is not themeable.

Low-end first

System fonts until the webfont lands, no blocking imagery above the verdict, no gradient that costs a repaint. The verdict must be readable at 100 nits and at 1,000.

Dense but calm

The console packs rows tightly and still resolves to one accent, one type family and one weight of rule. Density comes from spacing, not from ornament.

AA, 44px, never colour alone

4.5:1 for body, 3:1 for chrome, 44px minimum targets, and four redundant channels on every verdict.

The platform recedes

verifynNG appears once per screen, small, as attribution. The tenant owns the surface; the platform owns the meaning.

08 — Decisions

Everything unspecified, and what I chose.

Each of these is reversible. Flag any you disagree with before the component set is built on top of them.

Platform typefaces
Space Grotesk for display, IBM Plex Sans for UI, IBM Plex Mono for codes. All three are open, hint well at small sizes on low-end Android, and stay clear of Inter and Roboto so a tenant swapping to Inter reads as a deliberate change.
Platform accent is slate-blue
Green, amber, red and plum are spent on verdicts. A slate-blue accent leaves the whole verdict range unambiguous and reads as chrome rather than as a signal.
Tier 1 and tier 2 share a hue
Two adjacent greens would be indistinguishable to a deuteranope and in sunlight. Both positives use #0E6E58; the tier is carried by the notch signature, the glyph and the label.
Utility states are neutral
Invalid, rate-limited and error take steel grey, not a verdict hue. They describe the request, not the product, and colouring them red would teach consumers that a network failure means a fake.
Unknown and counterfeit are one state
The platform cannot tell them apart — the absence of a record is all it has. “Not recognised” with plum and a hatched band; the copy names counterfeiting as a possibility, not a finding. Split them only if the epics carry separate enums.
Consumer web is light-only
Dark is a console affordance. A tenant-themed dark consumer surface multiplies the contrast-guard surface area with no clear benefit under the sunlight constraint.
Radius as a multiplier
Tenants set one number, clamped 0–2, rather than three independent radii. Preserves the ratio between inline, card and sheet corners across every tenant.
Broadsheet is the documentation voice
The bound design system styles these specification pages. The artboards inside them render in verifynNG's own tokens, which is the thing being specified.
Enum strings are provisional
The repository is empty on main, so E06/E07/E08 could not be read. Names here follow the brief and are the one thing in this document I expect to change on first sync.
