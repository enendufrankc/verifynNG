# Retention Schedule

Every row is a policy registered in `apps/api/src/modules/retention/retention-runner.service.ts` (`GET /v1/retention/policies` lists them live). Policies run nightly (`RETENTION_CRON`, default `0 2 * * *`) via `RetentionScheduler`, and can be triggered on demand by platform support via `POST /v1/retention/run`. **A wet run always requires a dry run for that policy within the last 24 hours** — the server returns 409 otherwise. Every run, dry or wet, writes a `RetentionRun` row (policy, cutoff, matched, affected, error) and emits a `retention.executed` event; a policy failing never stops the others.

## Never deleted

- `ConsentRecord` and `PolicyDocument`/`PolicyAcceptance` — these tables _are_ the compliance evidence (proof of what was published and what was agreed to). Deleting them would defeat their purpose.
- `AuditLog`, `UsageSummary`, `Incident` — explicitly excluded from `tenant.offboarded.purge`, per the epic's own decision that regulatory/financial/security records outlive the tenant.
- `ScanEvent.verdict`/`tier`/`geoCountry` and row itself — anti-counterfeit evidence, kept indefinitely (see `docs/compliance/data-map.md`'s DPIA note).

## Legal holds

`LegalHold(scope, ref, reason)` — created via `POST /v1/legal-holds` (platform support only) — blocks a legal-hold-aware policy from touching the held subject until released (`POST /v1/legal-holds/:id/release`). Consumer DSAR erasure also checks for a `LegalHold(scope: consumer, ref: <subjectHash>)` before erasing and returns `rejected_legal_hold` if one is active.
